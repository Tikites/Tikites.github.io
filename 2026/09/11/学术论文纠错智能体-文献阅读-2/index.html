第二次论文阅读：ScholarGEC

论文基本信息

论文： ScholarGEC: Enhancing Controllability of Large Language Model for Chinese Academic Grammatical Error Correction
作者： Zixiao Kong, Xianquan Wang, Shuanghong Shen, Keyu Zhu, Huibo Xu, Yu Su
会议： AAAI 2025
任务： 中文学术论文语法错误纠正

ScholarGEC 针对一个非常具体的问题展开：

LLM 在普通 GEC 中已经具有很强的纠错能力，但面对中文学术文本时，仍然容易出现严重的 over-correction。

论文将这一问题归因于两个方面：

  1. LLM 对专业领域知识理解不足；
  2. LLM 在 GEC 任务中的可控性不足。

从 DeCoGLM 到 ScholarGEC：问题进一步出现

DeCoGLM 给出了一个重要答案：

通过 Detection-Correction 结构限制 LLM 的修改范围。

那么自然会产生一个问题：

如果 Detection 本身判断错了怎么办？

尤其是在学术文本中。

论文中给出了一个例子：

矿物组成

对于专业领域来说可能是一个完全正确的术语。

但如果 LLM 不理解这个领域知识，就可能认为：

矿物组成

不是自然表达，从而进行修改：

矿物组成成分

矿物组成

这种：

domain-specific knowledge deficiency

也就是：

领域知识不足。

是Over-Correction的核心原因之一

ScholarGEC 的核心问题

因此 ScholarGEC 实际上面对两个问题：

Domain Knowledge Deficiency+Poor Controllability\boxed{ Domain\ Knowledge\ Deficiency + Poor\ Controllability } Domain Knowledge Deficiency+Poor Controllability​

进一步导致：

Over-Correction\boxed{ Over\text{-}Correction } Over-Correction​

论文的核心目标不是：

让 LLM 发现更多错误。

而是：

让 LLM 更准确地判断“什么其实不是错误”。

这一点非常重要。

因为对于学术论文纠错：

Precision>FluencyPrecision > Fluency Precision>Fluency

至少不能为了追求语言流畅度而牺牲原文正确内容。

ScholarGEC 的整体框架

ScholarGEC 可以概括成：

Input→Knowledge Integration→Detection→CorrectionInput \rightarrow Knowledge\ Integration \rightarrow Detection \rightarrow Correction Input→Knowledge Integration→Detection→Correction

同时在生成过程中加入：

Special Token + Iterative Self-Reflection

整体框架为：

论文明确提出通过 disciplinary knowledge prefixes 增强领域知识理解，同时使用 Detection-Correction 分离结构提高可控性，并加入 special token 与 iterative self-reflection。

Knowledge Integration

需要注意

ScholarGEC 并不是简单地把整个领域知识库直接塞给 LLM。

它采取的是：

Input→Retrieve Relevant Knowledge→Generate PrefixInput \rightarrow Retrieve\ Relevant\ Knowledge \rightarrow Generate\ Prefix Input→Retrieve Relevant Knowledge→Generate Prefix

也就是说：

针对当前输入句子寻找相关领域知识。

它不是简单塞入知识库，而是针对当前句子，与结构化知识通过词嵌入映射到同一片语义空间，根据余弦相似度检索相关知识，再将其转化为 disciplinary prefix。

Knowledge Retrieval

首先：

知识库中的候选知识也进行类似的表示。

然后通过语义相似度寻找：

与当前句子最相关的领域知识。

可以抽象为：

k∗=arg⁡max⁡k∈Ksim(E(x),E(k))k^* = \arg\max_{k\in K} sim(E(x),E(k)) k∗=argk∈Kmax​sim(E(x),E(k))

其中：

  • xxx：当前输入句子
  • KKK：领域知识库
  • E(⋅)E(\cdot)E(⋅)：embedding
  • simsimsim：语义相似度

因此，模型并不是面对整个知识库，而是面对：

与当前句子最相关的一小部分知识。

Disciplinary Prefix

得到相关知识后，并不是直接把原始知识交给 Detection。

论文进一步利用 LLM 对知识与原句进行分析，生成更加适合当前任务的：

disciplinary knowledge prefix

最终：

Prefix+Input→GEC ModelPrefix + Input \rightarrow GEC\ Model Prefix+Input→GEC Model

这个 Prefix 的作用可以理解为：

在模型进行纠错之前，先告诉它“这个句子处于什么专业语境下”。

因此：

如果模型获得了相关矿物学知识，就更有可能认识到：

这是一个专业术语，而不是一个普通语言错误。

Special Token：增强“无错误”判断

ScholarGEC 进一步发现：

GEC 中不仅要识别错误，还必须稳定地识别“没有错误”。

因此 Detection 阶段加入特殊 token。

它的目的可以理解为：

Input→{ErrorNo ErrorInput \rightarrow \begin{cases} Error\\ No\ Error \end{cases} Input→{ErrorNo Error​

特别强调：

No Error 是一个需要模型明确做出的判断。

而不是让模型默认：

“既然让笔者纠错，那笔者就应该修改些什么。”

这实际上是在从任务定义层面抑制 over-correction。

Detection-Correction

这里 ScholarGEC 与 DeCoGLM 出现了明显的联系。

ScholarGEC 重新采用：

Detection→CorrectionDetection \rightarrow Correction Detection→Correction

而不是传统的：

Input→Seq2Seq→OutputInput \rightarrow Seq2Seq \rightarrow Output Input→Seq2Seq→Output

因此：

DeCoGLM 让笔者理解了 Detection-Correction 为什么能够提高 GEC 的 controllability；

而 ScholarGEC 进一步说明：

这种 controllability 对学术论文纠错尤其重要。

Iterative Self-Reflection

这是笔者认为 ScholarGEC 对研究很值得借鉴的部分。

它不是简单地：

而是：

生成→评价→重新生成\boxed{ 生成 \rightarrow 评价 \rightarrow 重新生成 } 生成→评价→重新生成​

也就是：

Verification / Refinement Loop

为什么 Self-Reflection 有意义？

对于 GEC：

Input→CorrectionInput \rightarrow Correction Input→Correction

模型可能生成一个看起来更加流畅的句子。

但这并不意味着：

它真的应该修改。

因此可以加入一个独立评价过程：

这样模型不仅负责：

“提出修改”

还需要：

“检查这个修改是否合理。”

这已经开始从单纯的 generation 转向：

generation + verification

Counterfactual Augmentation

ScholarGEC 在知识 prefix 的优化过程中进一步引入：

Counterfactual Augmentation

其目的不是简单增加训练数据，而是帮助模型避免学习：

虚假的相关性。

也就是说：

如果某些知识和某个句子在训练数据中经常同时出现，模型可能错误地认为：

“只要看到这个词，就应该按照这个知识修改。”

Counterfactual augmentation 试图通过构造反事实情况，降低这种 spurious correlation。

因此它与知识 prefix 的目标是一致的：

让模型真正依据领域知识判断，而不是形成错误的表面关联。

DeCoGLM 与 ScholarGEC 的关系

笔者认为可以把两篇论文看成一个连续的问题链。

阅读收获

收获一：学术论文纠错与普通 GEC 有本质区别

学术文本中存在：

  • 专业术语
  • 固定表达
  • 学科特有句式
  • 作者有意使用的表达

因此：

“更流畅”不等于“更正确”。

收获二：纠错系统必须具有“拒绝修改”的能力

一个好的 GEC Agent 不应该只有：

What should I change?

还应该能够回答：

Should I change anything at all?

这意味着：

No ErrorNo\ Error No Error

本身就是一种重要的预测结果。

收获三：知识增强不应该只是“把知识塞给模型”

ScholarGEC 的 Knowledge Integration 给笔者的启发是：

Input→Relevant Knowledge→Task-Specific ContextInput \rightarrow Relevant\ Knowledge \rightarrow Task\text{-}Specific\ Context Input→Relevant Knowledge→Task-Specific Context

比：

Input+Entire Knowledge BaseInput + Entire\ Knowledge\ Base Input+Entire Knowledge Base

更加合理。

收获四：Self-Reflection 的真正价值在于 Verification Loop

笔者认为最值得迁移到自己研究中的不是：

“让 LLM 自笔者反思。”

而是：

Generate→Evaluate→Refine\boxed{ Generate \rightarrow Evaluate \rightarrow Refine } Generate→Evaluate→Refine​

这是一种通用的 Agent 工作模式。

对笔者的“学术论文纠错 Agent”的启发

结合两篇论文，笔者目前对自己的研究方向有了一个更加清晰的认识。

笔者不认为最终系统应该是：

Paper→LLM→Corrected PaperPaper \rightarrow LLM \rightarrow Corrected\ Paper Paper→LLM→Corrected Paper

而应该是一个具有明确职责划分的系统。

例如：

这里 DeCoGLM 提供了：

Detection → Correction

的基本结构。

ScholarGEC 提供了：

Domain Knowledge + Special Token + Self-Reflection

等进一步控制手段。

而笔者的研究可以进一步把这种思想扩展成：

多错误类型 Detection → 专门化 Correction → Verification → User Confirmation

最终只执行：

User Approved ChangesUser\ Approved\ Changes User Approved Changes

而不是让 Agent 擅自重写全文。
