计算机网络基础概念

主要问题

计算机网络课程主要探讨四个对象，包括网络中存在的对等实体——谁与谁通信，计算机网络所要实现的服务——能提供什么，以及应用的相关协议——按照什么规则通信，和实现与管理——具体怎么做出来并让他持续运行

可以一定程度上简要讨论一下

对等实体

存在网络中的实体并不只是你我，这样通过主机交流的两个真实存在，也就是不能单单将接入网络的电子设备当成实体，否则无法体现对等。其实稍加了解，可以知道计算机通信通过TCP/IP协议进行交流，每个主机在网络上的存在其实可以被剖解成由上到下多层的存在，交流中原始信息也会顺次被每一层封装，发送到网络中，然后到达目的节点时由下到上又依次拆包直到露出内部信息。网络中的每一个主机实体在不同层级采用的协议一致，都遵循相同的规则，所以同层的存在属于相同的协议层，并承担对应相同的功能，也就是对等的实体。由此观之，实则通信的本质是不同节点上的对等实体，也就是对等层通过协议进行逻辑通信。所以网络实体也就着重讨论网络的组成、命名以及结构

服务

在有了不同层级的实体概念后，需要讨论，不同层对于他的上下层有什么作用？这就是这些层级所要提供的服务。具体遵循，上一层使用下一层提供的服务，下一层通过自己的协议实现这个服务。具体每一层的作用后续中继续讨论

协议

这一层强调的就是对等实体之间到底怎么交流。因为网络通信是一个巨大的包装并解包过程，对于一个对等实体而言，他们通信时发出的东西和接收时接受的东西是同一结构的；通信时由上层接收的和接收时向上层发送的东西也是同一结构的，协议描述的就是对于这一层级而言他该怎么包装或者解包，同时定义好这一层信息的相关发送、处理规则。协议规定的内容包括：

  • 消息格式：数据长什么样？
  • 消息含义：每个字段是什么意思？
  • 发送时机：什么时候发送？
  • 接收规则：收到以后怎么处理？
  • 异常处理：丢包了怎么办？
  • 状态转换：什么时候进入什么状态？

需要与服务相区分，协议重点关注对等实体所共同遵循的规则，而服务重点关注下层要向上层提供什么服务，也即服务是垂直的，协议是水平的。

实现与管理

上述描述了理论上的网络结构，这一部分的内容则需要解决现实中该如何构造一个网络系统，该讨论物理具体实现的方式，定义协议到底怎么实现？网络怎么配置？怎么运行？怎么维护？即如何通过软硬件实现协议、如何配置网络、如何使网络正常运行，以及如何对网络进行监控、维护和管理。

网络的类别

接下来了解我们身边一般定义的网络都有哪些。一般网络可按覆盖范围划分，可以分成四类网络。需要注意这样划分的网络只是直观的划分依据，并非严格有覆盖面积的划分标准

个域网（PAN）

个域网（PAN, Personal Area Network）是围绕个人建立的小范围网络。典型范围通常是：几厘米到几米，主要服务于一个人的个人设备之间的通信。

常规可见的有NFC、蓝牙等常见的近距离通信技术

局域网（LAN）

局域网（LAN, Local Area Network）是我们日常接触最多的一类网络。它用于连接一个相对有限的地理区域内的大量计算机和网络设备，一般家庭用网络就是局域网，我们一般用的“Wi-Fi”就是局域网的一种实现技术

城域网（MAN）

城域网（MAN, Metropolitan Area Network），可以理解成：覆盖一个城市或城市区域的网络。它的覆盖范围比 LAN 大，但通常又没有 WAN 那么广，一般由若干个LAN组成

广域网（WAN）

广域网（WAN, Wide Area Network）是覆盖范围最大的这一类。它可以跨越：城市、省、国家、大洲、甚至全球，我们现在使用的Internet互联网就是典型的全球性互联广域网络（这里需要关注Internet、internet、WAN是三个不同的东西）

互联网（Internet）

作为世界上最大的网络结构，由多个子网构成，同时每个子网也可以进一步划分，一直到家庭范围甚至房屋的小局域网、个域网

ISP（Internet service provider）

网络运营商，譬如中国电信、中国移动这些，提供网络的接入与互联服务

总之，网络并不是一个巨大的、单一的网络，而是大量不同规模、不同所有者、不同技术的网络彼此互联形成的“网络的网络（network of networks）”。

网络的结构

网络边缘

这个元素代表通信的起点和终点的在哪里，也就是网络中直接产生和消费数据的终端设备以及运行在这些设备上的应用，这些设备被统称为端系统（End System）或主机（Host）。应该明白，网络边缘不只是“电脑”，而是强调通信的端点

主机

主机（Host）是一个设备/节点层面的概念，例如：个人电脑、手机、服务器等，它们作为网络通信的端点，能够运行网络应用、产生和接收网络数据。其功能是容纳应用程序，也即主机是网络应用运行的载体，也是网络通信的端点，可以将用户程序产生的数据向接入网发送，从网络接收数据并提供给应用程序。主机内部大致可以分为三部分：网络硬件、内核软件、用户软件。

网络硬件

**网卡（Network Interface Card, NIC）**是主机连接网络的硬件接口。例如有线以太网卡、Wi-Fi网卡、手机的蜂窝网络接口，这些都可以理解为网络接口设备，负责主机与外部网络之间的数据发送与接收。

一台主机可以拥有多张网卡，而每个网卡对应其全球唯一的MAC地址。

内核软件

主机上的各种软件进程无法直接调用网卡实现网络服务，而是需要间接的借助网卡的内核驱动来调用网卡实现功能，承担了一个中间协调者的角色。因为不同厂商开发的网卡的硬件接口和操作方式可能不同，也就需要不同的网卡驱动进行调用，最终实现一个通用的外部软件的调用接口。网卡驱动对外部软件的接口是统一的，这样外部软件只用实现网卡驱动的调用，不用关心不同网卡有怎样的调用方式

用户软件

这就是上述调用内核软件、网卡驱动的外部软件。这类程序通常不直接操作 TCP/IP 协议栈，而是使用操作系统提供的Socket API，简要提及一下，Socket API 是操作系统向应用程序提供的网络编程接口，使应用程序能够使用操作系统提供的网络通信能力，而无需直接处理底层网络协议和硬件。。这样应用程序不需要自己实现 TCP/IP 协议，而是通过 Socket API 向操作系统请求网络服务，具体的 TCP/IP 协议处理由操作系统内核中的网络协议栈完成。

主机的命名

主机在三个层次上可以有三个名字MAC地址、IP地址、主机名，分别定义主机数据链路层接口的标识，网络层上的接口标识，方便人类记忆使用的名字，关于他们的详细认知后续再描述

网络边缘仍可根据其在某次网络通信中所扮演的角色细分为两类：

客户端

一次网络服务中，向网络发送服务请求的实体。例如chrome、手机App这些都是客户端，浏览器建立在HTTP协议的基础上向web服务器发送了服务请求。此时浏览器就是客户端。也就是需要明晰客户端通常是运行在主机上的应用程序/进程，而不是主机本身，因为发送请求的往往不是主机本体，而是运行在上面需要网络提供服务的程序，这个思想同样可以迁移到对“服务器”的认识。

服务器

一次网络服务中，响应其他端系统的请求并提供服务的实体，例如web服务器这些。

需要注意，服务器和客户端的身份并非固定在某一个主机上，而是看他在某一次网络服务中所充当的角色而定。

接入网

了解了网络边缘成分，接下来需要了解链接网络边缘的成分，也就是构成网络的“边”——这些终端设备怎么进入互联网。这就是接入网，也即链接端系统与网络核心的网络。

接入网需要实现将某个主机连接到边缘路由器上，而边缘路由器就是端系统host去往任何其他远程端系统的路径上的第一台路由器

物理介质

在网络具体信息传播的时候，发射机与接收机之间的物理介质上传播的最小单元是位，即bit（比特）

存储常用字节Byte
K/M/G层级为2^10进制
传输常用比特Bit
K/M/G层级为10^3进制
而传递信息的实体即为具体的物理介质，介质分为两种

引导型介质

存在一个物理路径约束信号传播。典型的介质有双绞线、同轴电缆、光纤等

  • 双绞线

两根绝缘铜线相互缠绕形成一对(降低电磁干扰和串扰)
电话线：一对双绞线
网线：四对双绞线，广泛应用于计算机网络双向传输
网线接口：水晶头

  • 同轴电缆

两根同心铜导线，双向传输，电缆上的多个频率通道，带宽可达100Mbps。
注：同轴电缆采用了频分复用的技术，使得不同频率范围可以承载不同信号，因此同一条物理线路可以同时承载多个信道。

  • 光纤

光纤利用光信号承载数字数据
特点：

  • 高速运行：高速点对点传输，带宽高
  • 低误码率：中继器相距较远，抗电磁干扰
  • 传输距离长
非引导性介质

此类介质无需物理导线实体作为信号传播路径，也即无线电信号。其通过电磁频谱中各种“波段”携带信号，不依赖介质的传播。一般采用半双工的传播方式，包含类型简单列为下表

网络核心

网络核心的作用是将海量的端系统互连起来，解决进入网络之后，数据如何跨越大量网络设备，从一个端系统到达另一个端系统。可以理解为，网络核心就是有大量互联的路由器机器告诉链路构成的网络主体，负责在不同的端系统之间转发数据

端系统通过本地网提供商（Access ISP）接入Internet，然后网络提供商也要相互连接。一种选择是两两直接建立链路，但问题是后续加入的每个Access ISP也要和别的链接，导致可扩展性下降。另外一个选择则是定义全局ISP（Global ISP），每个本地的Access ISP链接本地全局ISP，全局ISP再相互链接。后续也出现了区域ISP（region ISP），链接Access ISP和Global ISP。

功能

网络的核心功能有两个：路由和转发

路由
  • 全局操作：计算通往目标主机的路径，即经过的结点（主机、路由器）序列
  • 实现：通过路由算法计算，结果存储在路由表里
转发
  • 本地操作：每个结点将数据交给路径上的下一跳
  • 实现：根据目的主机，查找本地路由表，确定下一跳

网络核心组成

可想而知，网络核心最重要的两个组成部分就是路由器以及相应链路。

路由器（Router）：决定数据包应该往哪里走，以及将数据包从输入接口转移到合适的输出接口。
链路（Link）:在路由器之间传输数据。

网络核心的基本工作就是利用它们完成数据在网络核心中的转发

工作方式：分组交换

网络核心并不是简单地建立一条固定线路，然后让数据一直通过这条线路传输。Internet 最核心的通信方式之一就是：分组交换（Packet Switching）它的基本思想是：将应用产生的数据划分成一个个较小的数据块，每个数据块作为一个分组（Packet）在网络中独立传输，每个分组首部都含有地址，独立地选择传输路径。

选用这种传输方式是因为网络资源是共享的，如果每条网络通信都长时间单独占用其使用的线路，这会严重占用网络资源。同时如果每两个用户之间都建立一条专用线路，网络资源会产生巨大的浪费。而分组交换允许不同用户的数据包共享同一条链路，按照一定规则交替传输自己的数据包。也即统计复用（Statistical Multiplexing）

数据传输中，使用存储-转发机制，每个路由器接受完整一个数据包之后（存储），才转发给下一跳→\rightarrow→但是这也导致了可能存在的额外的报文传输延迟

正常的链路传播延迟
将L位数据包，以R bps的速率，发送到链路中： 需要L/R秒
额外的传输延迟
中转路由器发送数据包前等待单个数据包传输完整的延迟

总的来说，分组交换实现了主机之间端到端通信可由多个路径构成，不同的分组可共享的使用同一节点或链路。

分组交换适合有大量突发数据

  • 更好的共享链路
  • 简单，不需要建立连接
    缺点1：分组交换容易拥塞，引起排队延迟甚至丢包
  • 需要设计可靠性机制与拥塞控制机制
    缺点2：分组交换无法提供服务质量保障
  • 语音、视频、游戏等服务需要带宽保障
  • 折中方法：虚电路
    用分组模拟电路交换行为
    自身开销大，性能难以保证（与正常的分组交换数据竞争带宽）
  • 目前仍然没有公认解决方案

另一种选择：电路交换

其实还有一种技术电路交换。这个技术中主机持续以数据流发送，先呼叫建立连接，实现端到端的资源预留。预留的的资源包括：链路带宽资源、交换机的交换能力电路连接建立之后，物理通路被通信双方独占，资源专用，即使空闲也不与其他连接共享。不适用现在互联网这种大量用户、通信具有突发性的网络，遂应用大幅减少。

电路交换的多路复用

  • 频分多路复用FDM
  • 时分多路复用TDM
  • ……
  • 在每一路上实现具有和专用链路类似的性能
  • 该路资源专用，即使空闲也不与其他连接共享

电路交换 VS 分组交换

交换方式

电路交换

  • 需要建立连接
  • 为每个连接预留资源
  • 有性能保障
  • 难以实现灵活复用

分组交换

  • 随时发送，无需连接
  • 没有预留资源，但较灵活
  • 抗毁性强（可以切换路线）
  • 在传送突发数据时可提高网络利用率

Eg:

1 Mb/s 链路
每个用户:
传输数据时占用100 kb/s带宽
10%的时间在传输数据
电路交换:
最多支持10个用户
分组交换:
对于35个用户, >10个用户同时传输数据的概率： 小于 0.0004
计算方法：二项分布

计算机网络的服务

无论分组交换还是电路交换，从应用程序的角度都是与网络上的其他应用程序交互，发送 / 接收消息。不同应用的需求有很大的差异，按照网络的调用方式，可以分为面向连接与无连接两大类服务类型

面向连接的网络服务

此类服务也即传输数据之前，先建立对话联系，每个“请求”或“响应”后，都在对方产生一个“指示”或“确认”动作
类比电话系统模型建立的（一个常见的例子）

拨姑姑家的电话号码。
她家的电话铃响了。
她拿起电话。
你听到响铃停止。
你邀请她来喝茶。
她听到了你的邀请。
她说她很高兴来。
你听到她接受邀请。
你挂断电话。
她听到了，也挂断电话。

无连接的网络服务

这类服务数据传输前不需要事先建立连接
类比邮政系统模型建立的（一个常见的例子）

有快递要发给朋友
快递员上门取件
快递进入区域集散中心
区域集散中心通过运输系统发到目的地
区域集散中心分发给目的地快递员
快递员按照地址派送

网络服务的性能指标

带宽

  • 网络中某通道传送数据的能力，即单位时间内网络中的某信道所能通过的最高数据率
  • 单位是 bit/s，即 “比特每秒”，也可以写为bps (bit per second)，或 kbit/s、Mbit/s、 Gbit/s等

包转发率(PPS)

  • 全称是Packet Per Second(包/秒)，表示交换机或路由器等网络设备以包为单位的转发速率
  • 线速转发：交换机端口在满负载的情况下，对帧进行转发时能够达到该端口线路的最高速度

在交换机上：大包和小包，哪个更容易实现线速？
大包：数据转发时，交换机需要处理的包的数量更少

比特率 (bit rate)

  • 单位时间内，主机往数字信道上传输数据的数据量，也称数据率或传输速率，单位是b/s
  • 前面接入网里介绍的传输速率，指的都是比特率

吞吐量 (throughput)

  • 单位时间内，通过某个网络位置(或信道、接口)的数据量，单位是 b/s

有效吞吐量(goodput)

  • 单位时间内，目的地正确接收到的有用信息的数目，单位b/s（比如说响应送进行的数据传送就不算在有效吞吐量的计算范畴）

利用率

  • 信道利用率指出某信道有百分之几的时间是被利用的
  • 利用率=吞吐量/带宽
  • 网络利用率则是全网络的信道利用率的加权平均值

丢包率

  • 所丢失数据包的数量占所发送数据包的比率

时延(Delay)

时延 (delay 或 latency) 是指数据（一个报文或分组）从网络（或链路）的一端传送到另一端所需的时间，也称为延迟，可以分为四类具体时延

传输时延(transmission delay)

数据从结点进入到传输媒体所需要的时间，传输时延又称为发送时延或注入时延。这一部分的时延发生在数据处理节点上，是他将数据从自己传输到传输介质上所花费的时间

发送时延=数据帧长度(b)/信道带宽(b/s)发送时延 = 数据帧长度(b) / 信道带宽(b/s) 发送时延=数据帧长度(b)/信道带宽(b/s)

传播时延(propagation delay)

电磁波在信道中需要传播一定距离而花费的时间

传播时延=信道长度(m)/电磁波在信道上的传播速率(m/s)传播时延 = 信道长度(m) / 电磁波在信道上的传播速率(m/s) 传播时延=信道长度(m)/电磁波在信道上的传播速率(m/s)

处理时延(processing delay)

主机或路由器在收到分组时，为处理分组（例如分析首部、提取数据、差错检验或查找路由）所花费的时间

排队时延(queueing delay)

分组在路由器输入输出队列中排队等待处理所经历的时延

分组在一个缓冲区中排队，等到链路可用
若队列被填满，后续分组就被丢弃

四种时延中，排队时延是最不确定因素，其他3类时延都能相对容易计算，由此诞生了
排队论：广泛应用于计算机网络进行性能分析
排队论基本要素

  • 到达模型：分组怎样到达，平均到达速率A，峰值到达速率P
  • 平均等待时间W
  • 平均队列长度L
    Little’s Law (1961):

L=A×WL = A × W L=A×W

但是在现实中： L容易测量得到，A与W相对困难

总时延=发送时延+传播时延+处理时延+排队时延总时延 = 发送时延 + 传播时延 + 处理时延 + 排队时延 总时延=发送时延+传播时延+处理时延+排队时延

往返时延RTT(Round-Trip Time)

  • 从发送方发送数据开始，到发送方收到来自接收方的确认，经历的总时间
  • 可用于判断网络的通断性、测试网络时延、计算数据包丢失率等

时延带宽积

时延带宽积=传播时延×带宽时延带宽积 = 传播时延 × 带宽 时延带宽积=传播时延×带宽

*即按比特计数的链路长度。
*若发送端连续发送数据，则在发送的第一个bit即将达到终点时，发送端就已经发送了时延带宽积个bit ，而这些bit都在链路上向前移动。

  • 只有在代表链路的管道都充满比特时，链路才得到了充分利用。
  • 一般而言，时延带宽积越大越好，说明链路所能容纳的数据越多

时延抖动

  • 变化的时延称为抖动（Jitter）
  • 时延抖动起源于网络中的队列或缓冲，抖动难以精确预测
  • 在语音、视频多媒体业务中，抖动往往会严重影响用户的体验

延迟丢包

  • 在多媒体应用中，由于数据包延迟到达，在接收端需要丢弃失去使用价值的包。（比方说按序列顺序到达的数据包要是后面的包先到了，错位的前面的包即可能需要丢弃）

一个包是否被丢弃，主要看：
到达时间 > 播放截止时间
如果还没到截止时间，即使乱序，也可以先缓存，等前面的包到了再按序播放。

其他指标

  • 可靠性：发送的每个消息，接收方收到一次且仅收到一次

  • 完整性：发送的数据无法被篡改

  • 隐私性：发送的数据不被第三方截获，有时也包含发送方身份不被暴露

  • 可审计性（accountability）：可追溯用户的传输行为

网络协议

网络协议（Network Protocol）是一组规定网络通信双方应该如何进行通信的规则。
这里的“双方”不一定是两台电脑，更准确地说，是两个通信的对等实体（Peer Entities），它们为进行网络中的数据交换而建立的规则、标准或约定，即网络协议(network protocol)。通过网络协议，要实现或解决表明身份、可靠性、资源分配、拥塞问题、自适应性、安全问题等任务功能

  • 通信双方需要共同遵守，互相理解
  • 发送方：发送某个消息时，应满足特定条件
  • 接收方：收到某个消息后，要完成特定的工作
    三要素
  • 语法：规定传输数据的格式（如何讲）
  • 语义：规定所要完成的功能（讲什么）
  • 时序：规定各种操作的顺序（双方讲话的顺序）

协议封装

网络协议以头部封装的形式定义，每个协议定义自己头部信息，数据被封装为协议载荷，头部定义了如何处理分组

数据包=头部（Header）+载荷（Payload）数据包 = 头部（Header）+载荷（Payload） 数据包=头部（Header）+载荷（Payload）

  • 基本传输
  • 性能、各种可靠性保障
  • 哪些功能是必须的，哪些是可选的？
    同一个目标，可以有多种实现方式，比如：
    丢包重传：由端系统实现 or 由网络核心实现
    考虑：
  • 易于管理与扩展
  • 易于新技术更新迭代
    网络资源管理
  • 将链路、交换能力、队列分配给不同应用程序
  • 需要兼顾效率、公平与管理开销

分层架构：解决复杂系统

分层是计算机科学中的基本思想，广泛应用于个领域。计算机网络采用分层架构，是为了把一个极其复杂的网络通信问题拆分成若干相对独立、功能明确的子问题，使网络协议能够被设计、实现、维护和扩展通过分层，可以实现

  • 每层提供特定功能与服务保障
  • 层与层之间有接口调用
  • 同层实体通过该层协议进行对话
  • 屏蔽各层实现细节
  • 明晰简化，便于分析学习
  • 各层独立，加速技术演进
  • 统一接口，确保技术互通（interoperable）

这样降低复杂结构不同层次的耦合性，只需统一接口，内部实现和各层问题都能单独在层内解决，无需整个系统大改

分层的坏处也存在一些坏处，譬如引入额外开销，另外保留跨层信息有时候也很重要

计算机网络的经典分层

OSI参考模型

物理层（Physical Layer）

  • 定义如何在信道上传输0、1：Bits on the wire
  • 机械接口（Mechanical）：网线接口大小形状、线缆排列等
  • 电子信号（Electronic）：电压、电流等
  • 时序接口（Timing）：采样频率、波特率、比特率等
  • 介质（Medium）：各种线缆、无线频谱等
    …

数据链路层 (Data Link Layer)

  • 实现相邻（Neighboring）网络实体间的数据传输
  • 成帧（Framing）：从物理层的比特流中提取出完整的帧
  • 错误检测与纠正：为提供可靠数据通信提供可能
  • 物理地址（MAC address）：48位，理论上唯一网络标识，烧录在网卡，不便更改
  • 共享信道上的访问控制（MAC）：同一个信道，同时传输信号。如同：同一间教室内，多人同时发言，需要纪律来控制
  • 流量控制，避免“淹没”（overwhelming）:当快速的发送端遇上慢速的接收端，接收端缓存溢出

网络层 (Network Layer)

  • 将数据包跨越网络从源设备发送到目的设备（host to host）
  • 路由（Routing）：在网络中选取从源端到目的端转发路径，常常会根据网络可达性动态选取最佳路径，也可以使用静态路由
  • 路由协议：路由器之间交互路由信息所遵循的协议规范，使得单个路由器能够获取网络的可达性等信息
  • 服务质量（QoS）控制：处理网络拥塞、负载均衡、准入控制、保障延迟
  • 异构网络互联：在异构编址和异构网络中路由寻址和转发

会话层 (Session Layer)

  • 利用传输层提供的服务，在应用程序之间建立和维持会话，并能使会话获得同步

表示层（Presentation Layer）

  • 关注所传递信息的语法和语义，管理数据的表示方法，传输的数据结构

应用层（Application Layer）

  • 通过应用层协议，提供应用程序便捷的网络服务调用

TCP/IP参考模型

TCP/IP参考模型：ARPANET所采用

  • 以其中最主要的两个协议TCP/IP命名
  • Vint Cerf和Bob Kahn于1974年提出

网络接口层（Host-to-network Layer）

  • 描述了为满足无连接的互联网络层需求，单跳链路必须具备的功能，关注当前这一跳，如何把数据从一个网络节点送到相邻的网络节点。

互联网层（Internet Layer）

  • 通过多跳连接，将数据包独立的传输至目的地，并定义了数据包格式和协议（IPv4协议和IPv6协议），负责将数据报从源主机跨越多个互联网络送到目的主机，核心机制是 IP 寻址和路由。

传输层（Transport Layer）

  • 允许源主机与目标主机上的对等实体，进行端到端的数据传输：TCP，UDP。这里的端到端强调的是端口到端口之间的交流。传输层通过端口号等机制，把数据交给正确的进程。

应用层（Application Layer）

  • 传输层之上的所有高层协议：DNS、HTTP、FTP、SMTP…，定义应用程序之间交换数据的规则。

Eg
浏览器 →\rightarrow→ HTTP请求 →\rightarrow→ Web服务器
浏览器 ←\leftarrow← HTTP响应 ←\leftarrow← Web服务器

层 核心问题
应用层 A 上的浏览器和 B 上的 Web 服务说什么、怎么说？
传输层 A 上的浏览器进程和 B 上的 Web 服务进程怎么可靠/高效地传输数据？
网络层 数据报从 A 到 B 应该经过哪些网络/下一跳？
网络接口层 数据这一跳具体怎么从当前节点送到相邻节点？

OSI模型与TCP/IP模型比较

7层模型与4层模型

  • TCP/IP模型的应用层包含了OSI模型的表示层与会话层

基本设计思想：通用性与实用性

  • OSI：先有模型后设计协议，不局限于特定协议，明确了服务、协议、接口等概念，更具通用性
  • TCP/IP模型：仅仅是对已有协议的描述

无连接与面向连接

  • OSI模型网络层能够支持无连接和面向连接通信
  • TCP/IP模型的网络层仅支持无连接通信（IP）

OSI模型是事先定义好，然后期望后续网络结构参考此模型建立，而TCP/IP协议则是建立在TCP、IP两个协议诞生后的基础上，协议的需求所后续实现的四层协议，两者的构想提出存在一些差异

网络分层的实现

端系统：实现所有分层

  • 用户程序运行在端系统
  • 比特流进入系统，要一直传递给用户程序

边缘网与网络核心：实现第1层到第3层功能

  • 交换机：物理层与数据链路层功能
  • 路由器：实现前3层功能：物理层、数据链路层、网络层

传统交换机：不支持多跳传输

  • 收到一个分组，只有在目的主机与交换机直连的情况下，才能正确转发

传统路由器：支持多跳传输

  • 分组的目的主机可以与该路由器间隔多跳

现代交换机与路由器已经不做区分

  • 都支持二层与三层转发
  • 大部分技术资料中，两个名字混合使用
特征

特征1：复杂功能由端系统实现

  • 摒弃电话系统中“笨终端&聪明网络”的设计思路
  • 端对端原则：采用聪明终端&简单网络，由端系统负责丢失恢复等复杂功能
  • 实现了建立在简单的、不可靠部件上的可靠系统
  • 好处：简单的网络大大提升了可扩展性

特征2：以IP协议为核心

  • 可在各种底层物理网络上运行(IP over everything)
  • 可支持各类上层应用(Everything over IP)
    好处：
  • IP分组独立处理，网络核心功能简单（通过路由表转发分组），适应爆炸性增长
    容易实现多个网络互连：只要都支持IP
    屏蔽上层应用与底层通信
    两者可独立进行创新
